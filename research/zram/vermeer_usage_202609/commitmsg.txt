feat(companion): fragmentation-gated zsmalloc compaction, FanZiyun authorship (v0.4.0)

The on-device squeeze experiment (vermeer, 5.15.215-FanZiyun) proved the
missing half of the companion's job: after a kill-storm, mm_stat showed
mem_used_total 352 MB against a compr_data_size of 186 MB -- 89% zsmalloc
fragmentation. One full pass through /sys/block/zram0/compact took under a
second and returned 105 MB (healthy overhead afterwards: 3.3%); the
supervisor's recompression sweeps never reclaimed that.

- zram-policy.sh: abk_zram_compact_if_fragmented() -- one full pass (the
  compact node's "100" = 100 percent of zspages) per sweep tick, only when
  mem_used_total - compr_data_size > zram.compact.min_waste_mb (MiB) AND
  mem_used_total > compr_data_size * (1 + zram.compact.waste_pct / 100).
  Verdict and log line come from the same single awk pass (byte math never
  touches this ROM's 32-bit shell; see the mksh traps in plan.md); a kernel
  without the compact node is skipped silently. Rides the recompression
  clock: zram.recomp.enable=0 stops the sweeps and the gate together.
- common.sh / tunables.conf: three keys, defaults ON 1/50/15, registered in
  abk_known_keys; the two numeric keys clamped 1..1024 / 1..500 with a warn
  on junk, and the enable uses the repo-wide `= "1"` convention.
- module.prop: author corrected to FanZiyun (the previous value was the
  upstream repo mirror's handle, not the kernel/device authorship this
  ships under); v0.4.0 / versionCode 4; description now names the pass.
  module.conf carries the same clause in all three description fields, and
  ABK_MODULE_VERSION / ABK_MODULE_SET_VERSION 0.15.0 -> 0.16.0.
- tests: scenario 10 (go / healthy-skip / disabled / missing-node), the
  supervisor-tick compact-node write, the shipped defaults pinned both
  statically (tunables.conf lines) and dynamically (the up line must carry
  compact=1>50MB+15%), so a silent default drift goes red.
- README / plan.md / AGENTS.md: the stale "only thing on by default" row
  corrected, the Two-jobs preamble updated, ranges documented, and the
  measured rationale recorded where it belongs.

On-device verification after the in-place upgrade: healthy device produced
zero writes and zero log lines; forcing the thresholds to 1MB/1% wrote the
real compact node from the su context and reclaimed a further 0.4 MB
(175.69 -> 175.27 MB, pages_compacted 44699 -> 44802).

Gates: bash -n green (incl. ksu/*/*.sh); unit suite green, including the ten
new compaction assertions.
